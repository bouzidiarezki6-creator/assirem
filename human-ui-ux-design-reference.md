# Human UI/UX Design Reference

## Purpose

Use this document as a design reference when creating or improving web interfaces.

The goal is to produce interfaces that feel **natural, intentional, polished, and human-designed**, rather than looking like generic AI-generated UI.

This reference is especially relevant for:
- Next.js applications
- React applications
- Tailwind CSS
- SaaS dashboards
- Landing pages
- Restaurant websites
- Booking/reservation websites
- Agency websites
- E-commerce interfaces
- Admin panels

---

## 1. Core Design Principle

Do not create a design simply because it is technically correct.

Create an interface that looks like a real product designed by a thoughtful human designer.

Prioritize:

1. Clarity
2. Usability
3. Visual hierarchy
4. Consistency
5. Natural spacing
6. Realistic content
7. Accessibility
8. Responsive behavior
9. Subtle interaction
10. Brand personality

Avoid the feeling of:

> "This was obviously generated by AI."

---

## 2. Avoid Generic AI UI Patterns

Do NOT automatically rely on:

- Excessive gradients
- Huge hero headings
- Excessive rounded cards
- Excessive glassmorphism
- Random floating blobs
- Purple/blue AI-style gradients everywhere
- Excessive shadows
- Too many badges
- Too many cards
- Excessive animations
- Every section being centered
- Huge empty spaces without purpose
- Repeated identical card layouts
- Excessive use of icons
- Decorative elements with no functional purpose
- Generic "Lorem ipsum" content
- Generic startup copy such as:
  - "Revolutionize your workflow"
  - "Unlock your potential"
  - "The future of..."
  - "Powerful. Simple. Fast."

These patterns can be used when they genuinely fit the product, but they should never be the default.

---

## 3. Visual Hierarchy

Every screen should have a clear hierarchy.

Determine:

- What should the user notice first?
- What should they understand second?
- What action should they take?
- What information can remain secondary?

Use differences in:

- Font size
- Font weight
- Spacing
- Contrast
- Position
- Density
- Color emphasis

Do not make every element visually important.

A good interface has:

**Primary → Secondary → Supporting information**

---

## 4. Typography

Choose typography deliberately.

Prefer:

- 1–2 font families maximum
- Clear type scale
- Appropriate line height
- Comfortable paragraph width
- Strong hierarchy between headings and body text

Avoid:

- Too many font sizes
- Random font weights
- Extremely large headings everywhere
- Very tight line-height
- Long paragraphs spanning the entire screen

Typography should feel appropriate for the brand.

Examples:

- Luxury → elegant, restrained typography
- Technology → clean and precise
- Restaurant → warm and expressive
- Finance → trustworthy and structured
- Healthcare → calm and highly readable
- Creative agency → more experimental but still usable

---

## 5. Spacing

Use spacing intentionally.

Do not make everything equally spaced.

Create relationships between elements.

For example:

- Heading → subtitle: relatively close
- Section → next section: larger separation
- Label → input: close
- Input → next field: moderate
- Primary action → supporting action: visually connected

Use a consistent spacing system, but allow visual judgment when necessary.

The goal is:

**consistent, not mechanical.**

---

## 6. Layout

Do not make every page look like:

```text
Centered hero
↓
3 cards
↓
3 cards
↓
CTA
↓
Footer
```

Use layouts appropriate to the content.

Consider:

- Asymmetrical compositions
- Editorial layouts
- Split sections
- Full-width sections
- Dense information areas
- Quiet areas
- Side navigation
- Sticky elements
- Overlapping elements when appropriate
- Different content widths

The layout should follow the content, not force the content into a template.

---

## 7. Color

Use a restrained color system.

Define:

- Primary
- Secondary
- Background
- Surface
- Text
- Muted text
- Border
- Success
- Warning
- Error

Do not introduce a new color for every component.

Use accent colors strategically.

Color should communicate hierarchy and meaning, not just decoration.

---

## 8. Cards

Cards should have a purpose.

Before creating a card, ask:

> Does this content actually need to be separated from the surrounding content?

Avoid putting every piece of information inside a rounded rectangle.

Use:

- Cards
- Dividers
- Whitespace
- Typography
- Background changes

as different ways to group information.

---

## 9. Buttons

Buttons should communicate importance.

Recommended hierarchy:

### Primary
Main action of the page.

### Secondary
Useful alternative action.

### Tertiary / Ghost
Low-emphasis action.

Do not make every button look like a primary CTA.

Button text should describe the action.

Prefer:

- "Réserver maintenant"
- "Voir les disponibilités"
- "Ajouter au panier"
- "Contacter l'agence"

Avoid vague labels:

- "Learn More"
- "Click Here"
- "Get Started"

unless they genuinely fit the context.

---

## 10. Forms

Forms should feel simple and trustworthy.

Use:

- Clear labels
- Helpful placeholders only when necessary
- Visible validation
- Useful error messages
- Loading states
- Success states
- Disabled states
- Logical field grouping

Do not hide important information behind unnecessary interactions.

---

## 11. Navigation

Navigation should reflect the actual product.

Do not automatically create:

```text
Home
About
Features
Pricing
Blog
Contact
```

Only include sections that users actually need.

For mobile:

- Keep navigation simple
- Make important actions accessible
- Avoid overcrowding
- Preserve touch-friendly targets

---

## 12. Realistic Content

Use realistic content whenever possible.

Do not design around placeholder content that hides real layout problems.

Use realistic:

- Names
- Prices
- Dates
- Product titles
- Descriptions
- Statuses
- Images
- Addresses
- Notifications

Content length should be representative of the final product.

---

## 13. Images

Images should support the experience.

Choose image proportions based on the content.

Avoid:

- Random stock imagery
- Unrelated decorative images
- Excessive image usage
- Images that overpower the actual product

For luxury, hospitality, food, travel, and portfolio websites, imagery can be a major part of the visual identity.

---

## 14. Icons

Use icons consistently.

Prefer one icon family/style.

Do not use icons purely because there is empty space.

Every icon should either:

- communicate meaning
- support navigation
- improve scanning
- reinforce an action

Avoid decorative icon overload.

---

## 15. Animation & Micro-interactions

Animation should support the interface.

Use subtle:

- Hover transitions
- Button feedback
- Page transitions
- Loading states
- Modal transitions
- Expand/collapse interactions
- Scroll-based effects when appropriate

Avoid:

- Constant movement
- Excessive parallax
- Long animations
- Animation on every element
- Effects that slow down the user

A good rule:

> If the animation is more noticeable than the content, it is probably too much.

---

## 16. Responsive Design

Do not treat mobile as a smaller desktop.

Design for:

- Mobile
- Tablet
- Desktop
- Large screens

Consider:

- Navigation changes
- Text wrapping
- Image cropping
- Button sizes
- Content order
- Grid changes
- Touch targets
- Horizontal scrolling where appropriate

Check the actual layout at multiple viewport sizes.

---

## 17. Accessibility

Prioritize accessibility.

Check:

- Sufficient contrast
- Keyboard navigation
- Focus states
- Semantic HTML
- Form labels
- Alt text
- Touch target sizes
- Readable font sizes
- Reduced-motion considerations

Accessibility should be part of the design, not an afterthought.

---

## 18. Design Systems

For projects with multiple pages, establish reusable tokens and components.

Create a consistent system for:

- Colors
- Typography
- Spacing
- Radius
- Shadows
- Buttons
- Inputs
- Cards
- Modals
- Navigation
- Tables
- Alerts
- Badges

Do not create every page independently.

Reuse components while allowing layouts to remain contextually appropriate.

---

## 19. Human Imperfection

Natural design does not mean random design.

Allow controlled variation.

Examples:

- Different section compositions
- Different content densities
- Slightly different visual rhythms
- Editorial layouts
- Unequal column widths
- Intentional whitespace
- Strong focal points

Avoid making every section perfectly symmetrical.

The result should feel **designed**, not algorithmically repeated.

---

## 20. Design Before Code

Before implementing a major interface:

1. Understand the product
2. Identify the target user
3. Identify the main user task
4. Define the information hierarchy
5. Choose the visual direction
6. Define typography
7. Define colors
8. Define spacing
9. Define reusable components
10. Design the responsive behavior
11. Implement
12. Inspect the result
13. Iterate

Do not immediately start writing components without understanding the interface.

---

## 21. Use Figma When Appropriate

When Figma MCP is available:

- Inspect existing designs
- Reuse existing components
- Respect the design system
- Keep spacing and typography consistent
- Use real component structures
- Avoid recreating existing components unnecessarily

When creating a new design, establish the visual system before creating dozens of screens.

---

## 22. Browser-Based Visual Review

After implementation, inspect the actual rendered interface.

Check:

- Desktop
- Mobile
- Tablet when relevant
- Long text
- Empty states
- Loading states
- Error states
- Hover states
- Forms
- Navigation
- Images
- Overflow
- Alignment
- Spacing

Do not assume that a technically valid implementation is visually correct.

---

## 23. Final Quality Checklist

Before considering a UI finished, ask:

### Visual
- Does it look intentional?
- Is the hierarchy obvious?
- Is the typography balanced?
- Is the color palette coherent?
- Is there unnecessary decoration?

### UX
- Is the main action obvious?
- Can users understand the page quickly?
- Are interactions predictable?
- Are forms easy to use?

### Responsive
- Does it work naturally on mobile?
- Does content wrap correctly?
- Are buttons and inputs comfortable to use?

### Accessibility
- Is contrast sufficient?
- Are focus states visible?
- Are controls understandable without relying only on color?

### Human Design
- Does it feel like a real product?
- Does it avoid generic AI aesthetics?
- Is there a clear visual personality?
- Are variations intentional rather than repetitive?

---

## 24. Instructions for the AI Agent

When designing or implementing a UI:

1. **Analyze before coding.**
2. **Do not blindly use common AI UI patterns.**
3. **Prefer simplicity over decoration.**
4. **Use realistic content.**
5. **Create a coherent visual system.**
6. **Make hierarchy obvious.**
7. **Use whitespace intentionally.**
8. **Avoid excessive cards, gradients, shadows, and rounded elements.**
9. **Design mobile behavior explicitly.**
10. **Use accessible semantic components.**
11. **Reuse components without making every section identical.**
12. **Inspect the rendered result.**
13. **Fix visual inconsistencies after inspection.**
14. **Keep animations subtle and purposeful.**
15. **Optimize for the user's actual task, not for visual novelty.**

### Core principle

> **Build interfaces that feel like someone cared about the details.**
